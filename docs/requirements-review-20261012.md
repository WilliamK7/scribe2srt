## 2. 优先修正：自动恢复的边界过宽

涉及 `7200230`，位置：
[core/transcription_cache.py](../core/transcription_cache.py) 第 9–24 行，
[core/worker.py](../core/worker.py) 第 145–152 行，
[ui/main_window.py](../ui/main_window.py) 第 601 行。

当前逻辑在每次媒体处理开始时，仅通过“同主文件名 + 缓存修改时间不早于媒体”选择转录结果。
缓存文件没有记录来源文件身份、源语言或声音事件设置。这里把“继续原任务”扩大成了
“只要找到较新的同名文件，就自动跳过转录”。

已用临时目录直接核实两个选择行为，不涉及服务调用：

1. `same.mp3` 与 `same.mp4` 都映射到 `same.transcription-cache.json`。
   第一个输入留下的缓存较新时，第二个输入也会选择它。不同输入可误用同一份转录。
2. 只要 `movie.translation-cache.json` 存在，即使内容不是有效缓存，较新的普通
   `movie.json` 也会被选作转录结果。程序没有核对普通 JSON 是否由那个未完成任务生成。

此外，从调用关系可见，用户改变源语言或声音事件开关后重新发送同一媒体，也没有对应的
缓存失效判断。续传需求不能成为忽略新任务选项的理由。

**建议收缩：**保留真正的转录检查点与翻译结果缓存，但只复用属于同一来源及同一转录参数的任务。
删除普通 `.json` 的隐式自动发现分支；普通 JSON 继续通过用户明确导入的入口处理。
检查点名称保留完整媒体文件名或来源标识，记录并验证必要的任务身份。修改字幕排版或翻译模型
不应强迫重新转录，失效条件只覆盖影响转录结果的参数。

这是需要修正的行为，不是建议删除整个“失败后续传”功能。若本机还有旧格式未完成任务，
应保留文件并显式导入或做一次性迁移；不因没有正式 Release 就假定没有旧任务。

## 3. 可以缩减的具体实现

### A. 空翻译缓存标记：后续转录检查点已经取代其作用

位置：[core/subtitle_pipeline.py](../core/subtitle_pipeline.py) 第 43 行，
[core/translation.py](../core/translation.py) 第 116–121 行。

`TranslationCache.checkpoint()` 在尚无任何翻译结果、甚至验证密钥之前就写一个空缓存。
其注释说明用途是“配置失败时也能复用转录”。这是早期通过翻译缓存标记寻找普通转录 JSON 的设计。
现在 Worker 已在进入字幕处理前独立写入 `.transcription-cache.json`，该用途有了专门载体。

**建议删除空标记方法与调用，保留 `save_node()` 对已完成译文和拆批进度的保存。**
媒体输入通过专用转录检查点恢复；JSON 输入本身仍在。不要误删真正的翻译进度。
应与上一节的普通 JSON 兼容分支一起收缩，避免留下半套旧协议。

### B. 已无生产用途的私有入口、参数和辅助函数

| 位置 | 当前实际用途 | 建议 |
| --- | --- | --- |
| [core/srt_processor.py](../core/srt_processor.py) 第 305–315 行 `_generate_final_srt_content()` | 仓库生产代码不调用；仅两处测试引用。正式路径已是 `create_entries()` → `render_entries()` | 删除旧私有包装方法；保留公开 `create_srt_from_json()` 和输出契约验证 |
| [ui/main_window.py](../ui/main_window.py) 第 587、646 行 `from_batch` | 参数传入后完全没有读取 | 删除参数及调用处实参；无需改变 JSON 后台处理 |
| [core/windows_integration.py](../core/windows_integration.py) 第 41–42 行 `_ps_string()` | Unicode 改造后仅用于测试构造一个外部快捷方式 | 移到测试侧，或由现有 ShellLink 接口准备该测试对象 |

这些是小规模清理，不应包装成架构收益。判断依据是生产调用关系和需求接口，
不是“删了会不会让某条私有方法测试失败”。仓库外若有人调用私有方法，不在本次已核实范围内。

### C. 将许可证更新与每次打包分开

位置：[scripts/collect_licenses.py](../scripts/collect_licenses.py) 第 81–100 行。

Qt 的材料已经随仓库保存并校验；Python、OpenSSL、zlib、Expat 的材料却在每次打包时重新 `fetch()`。
即使依赖已经装好、EXE 已构建，打包仍依赖这些远程地址当时能否访问。

**建议取消“每次打包重新下载”这一环节，改为依赖版本更新时获取材料、记录来源及哈希；
普通打包只选择匹配版本的本地材料并校验。** 首次获取及升级时仍然需要更新操作。
这保留计划要求的原文、来源和版本匹配，减少正常打包的网络阻塞；不是删除许可证材料。

### D. 构建环境与交付内容的收集范围可以区分，但不能直接删锁文件中的行

位置：[scripts/collect_licenses.py](../scripts/collect_licenses.py) 第 24、66 行，
[scripts/update_license_sources.py](../scripts/update_license_sources.py) 第 45–70 行。

收集器按整个构建环境复制许可证，并将所选 Qt 仓库的跨平台材料整体带入 ZIP。
这比“实际打包依赖的材料”更宽。可把完整构建环境清单保留在构建记录中，
再按实际交付组件整理用户包内容；需先建立组件与材料的对应关系，本次不提供未经核实的删文件清单。
为节约少量包体积而引入更复杂的筛选维护，也未必划算，因此这是低优先级候选。

特别是 `requirements-build.txt` 里的 `PySide6_WebEngine`、`PySide6_Pdf` 看起来不用于字幕界面，
但本机已安装的 `PySide6==6.12.0` 元数据将它们列为依赖。**不能只删除锁文件这两行来宣称完成精简。**
若要改用更小的 Qt 分发组合，那是另一项依赖选型工作，需要核实实际导入与构建，不能混成清理。

### E. 发布文档中的一次性环境处置可归档

位置：[docs/windows-release.md](windows-release.md) 第 68 行起的 GitHub 前置条件等内容。

具体账号首次 Fork、某版 CLI 参数差异、本机凭据故障处置，是当时“补齐阻塞点、交给较弱模型执行”
计划的合理内容，但不必全部永久占据正常发布说明。可把一次性准备与排障记录归档，主文档保留
重复使用的构建、验证、标签发布步骤。保留发布操作文档本身仍符合已批准计划。

## 5. 建议的收缩顺序

1. **先处理会影响结果的缓存边界：**来源与转录参数匹配、移除普通 JSON 自动兼容。
2. **同批去掉空翻译缓存标记，**保留专用转录检查点及真实翻译进度。
3. **删除无生产用途的私有包装和参数，**范围小、用户行为不变。
4. **将许可证联网更新从每次打包中抽出。**
5. **最后再考虑材料范围与文档体量，**不为形式上的“少代码”牺牲现有需求或引入更复杂的维护。

若还希望大幅减少队列、递归拆批、可配置项等实现，需要重新缩小已经确认的产品需求；
本次没有把这种产品取舍冒充为无损清理。

## 6. 实施结果（2026-10-12）

已在工作区完成第 2 节及第 3 节 A–C 的修改：

- 转录检查点使用包含媒体扩展名的路径，例如 `movie.mp4.transcription-cache.json`，
  并保存版本化封装及任务身份。按用户选择，以规范化绝对路径、大小、纳秒修改时间识别媒体，
  不做全文件哈希；转录模型、源语言、声音事件、说话人识别及分段长度必须匹配。
  字幕排版及翻译设置不参与转录身份。内容变化但大小和修改时间都未变的情况无法检测。
- 磁盘恢复和内存重试均核对身份；内存任务不匹配时明确停止，要求重新选择输入。
  视频仅在检查点匹配时跳过提取音频。旧格式缓存和普通 JSON 不再自动发现、复用或删除，
  普通 JSON 的明确导入入口保留。
- 删除空翻译缓存标记、旧私有渲染包装、未使用的 `from_batch` 参数和 `_ps_string()`。
  专用转录检查点、有效译文和拆批进度的保存及成功清理均保留。
- Python、OpenSSL、zlib、Expat 材料按精确版本保存至 `third_party/native-licenses/`，
  `native-sources.json` 记录官方来源和 SHA-256。显式更新脚本负责联网，正常打包仅校验并复制，
  缺失版本或哈希不符直接失败；保留本地和现有 CI 两套运行时对应材料。

第 3 节 D、E 仍为低优先级候选，未进一步裁剪许可证、改换 Qt 分发或归档发布文档。
本次未推送或发布 Release。后续按用户要求清理了已被本报告取代的消融脚本、报告和临时实验目录，

# Scribe2SRT

Scribe2SRT 是一款专业的音视频转字幕工具。通过集成 ElevenLabs 语音识别技术和智能字幕分割算法，让字幕制作变得简单高效。

本仓库是 [cylind/scribe2srt](https://github.com/cylind/scribe2srt) 的公开 Fork，保留上游提交历史和全部样本，并提供 Windows x64 便携版。

## 🚀 主要特性

- 🎯 **高质量转录**：基于 ElevenLabs 先进的语音识别技术
- 🌍 **多语言支持**：支持中文、英文、日文、韩文等多种语言
- 📝 **专业字幕标准**：遵循 Netflix 等行业标准的字幕制作规范
- ⚡ **智能分割算法**：基于标点符号优先级的语义分割，保持句子完整性
- 🔄 **智能重试机制**：失败时自动保留临时文件，重试时快速恢复
- 🎨 **用户友好界面**：简洁直观的图形用户界面，支持拖拽操作
- 📊 **实时进度反馈**：清晰的进度显示和状态提示
- 🌐 **Qwen-MT 小批量翻译**：外语字幕上方原文、下方简中译文；中文字幕本地繁转简

## 💻 安装使用

### Windows x64 便携版

1. 前往 [Releases 页面](https://github.com/WilliamK7/scribe2srt/releases) 下载 Windows ZIP；同页提供 `.sha256` 校验文件。
2. **完整解压到可写目录**，运行 `Scribe2SRT.exe`，无需安装 Python。设置保存在 EXE 旁的 `settings.json`；`settings.example.json` 是无密钥示例。
3. **自动翻译默认开启**：处理外语前填写 Qwen API Key，或先关闭“自动翻译为简体中文”。标记为中文的 JSON 使用本地 OpenCC 繁转简，无需密钥。
4. **视频处理推荐安装 FFmpeg**：将 `ffmpeg` 和 `ffprobe` 一起加入 PATH。FFmpeg 不随 ZIP 分发；本地中文 JSON 处理无需 FFmpeg。

## 📖 使用方法

### 基本操作流程
1. **选择输入文件**
   - 点击"选择文件"按钮或直接拖拽文件到程序窗口
   - 支持三种输入类型：
     - **音频文件**：支持所有常见音频格式（MP3, WAV, FLAC, M4A, AAC, OGG 等）
     - **视频文件**：支持所有常见视频格式（MP4, MOV, MKV, AVI, FLV, WEBM 等）
     - **JSON 转录文件**：ElevenLabs 格式的转录数据

2. **配置处理选项**
   - **语言选择**：选择源语言或使用"自动检测"
   - **音频事件标记**：选择是否标记非语音事件（如笑声、掌声等）
   - **自动翻译为简体中文**：默认开启，可关闭并保存选择；首次处理外语时请填写“翻译设置”

3. **开始处理**
   - 点击"生成字幕"按钮开始转录
   - 程序会显示详细的处理进度

4. **获取结果**
   - 处理完成后，仅在源文件同目录输出 SRT 字幕，不额外保留转录 JSON
   - 程序会显示输出文件路径

### Windows“发送到”快捷转录

1. 打开程序，先设置源语言、声音事件、翻译、字幕和并发选项。源语言与声音事件开关会保存；旧配置默认自动检测、关闭声音事件。
2. 在菜单栏选择“系统集成 → 添加到发送到”。重复添加会更新快捷方式。
3. 在资源管理器选中一个或多个音视频或 JSON 文件，右键选择“发送到 → Scribe2SRT”，程序会显示进度并自动开始。Windows 11 可先选择“显示更多选项”。
4. 再次发送的文件会追加到同一窗口，依次处理；正在处理或等待的重复路径会忽略，已完成的文件可再次发送。文件夹和不存在的路径记为输入错误，有效文件继续处理，不扫描文件夹。

队列固定使用开始时的设置，追加文件沿用这些选项。含“发送到”任务的队列通过日志显示成功、失败及输出路径，失败后继续后续文件。“取消任务”会停止当前及待处理文件；取消收尾期间的新请求会提示稍后重新发送。

最初通过“发送到”打开的窗口，仅在所有任务成功且后台线程结束后自动退出。发生输入错误、处理失败、设置读写失败或取消时保留窗口；手动打开的窗口始终保留。仅手动处理时保留原有成功及重试对话框。通信失败会明确报告接收未确认；若提示任务可能已送达，请先检查主窗口。

快捷方式仅写入当前用户的 SendTo 目录。打包版指向当前 EXE，源码版指向当前 Python 环境的 `pythonw.exe` 和项目入口，支持中文及带空格的路径。移动程序或更换源码 Python 环境后，需要重新选择“添加到发送到”。移除时选择“系统集成 → 从发送到移除”，只删除本程序创建的快捷方式。

`settings.json` 固定放在程序目录：源码使用项目目录，打包版使用 EXE 所在目录。配置不会从发送文件的目录或打包临时目录读取；程序目录需允许当前用户保存设置。输出仍保存在源文件旁，完整成功后原子替换 SRT，失败或取消时保留已有字幕。

也可从命令行调用：

```powershell
uv run --locked python app.py --send-to -- "D:\视频 文件\中文.json" "D:\音频\example.mp3"
```



### 字幕质量标准

本工具遵循专业字幕制作标准：

- **时长控制**：默认最短 0.83 秒，最长 7.0 秒；时间冲突时优先缩短上一条，保持下一条起点，每条至少 1 毫秒且相邻条目不重叠
- **字幕间隔**：尽量保留设定间隔，空间不足时可缩小至零；同一毫秒开始的对白和音效合并，按原顺序保留全部文字
- **字符密度**：CJK 语言每秒最多 11 字符，拉丁语言每秒最多 15 字符
- **行长限制**：CJK 语言每行最多 25 字符，拉丁语言每行最多 42 字符
- **双语排版**：启用翻译时，外语条目严格两行，保留原文和完整译文，不额外折行；编号、时间轴和条目数不变
- **语义完整性**：优先保持句子完整，基于标点符号优先级分割

## ⚙️ 高级设置

### 字幕参数调整
通过"字幕设置"菜单可以调整：
- 字幕显示时长和间隔
- 字符密度限制
- 每行字符数限制

对白和音效共用最终时间轴校正。最短显示时长、字幕间隔和阅读速度要求在时间冲突时让位于不重叠；翻译沿用校正后的时间轴。此规则默认始终启用，仅影响重新生成的字幕。

### 大文件处理
- 自动分段处理长文件（90分钟以上）
- 支持并发处理，提升处理速度
- 智能重试机制，确保处理成功

### Qwen-MT 翻译设置

在“翻译设置”中填写阿里云百炼 API Key，选择与密钥一致的北京、新加坡或中国香港地域，可填写业务空间 ID。程序只生成官方服务地址，不支持第三方 Base URL。调用使用单条 `user` 消息、非流式响应及 `translation_options`，参见[官方翻译文档](https://help.aliyun.com/zh/model-studio/machine-translation)和[API 参考](https://help.aliyun.com/zh/model-studio/qwen-mt-api)。

默认模型 `qwen-mt-flash`；预置 `qwen-mt-plus`、`qwen-mt-lite`，也可填写其他官方 `qwen-mt-*` 文本翻译型号。默认每批 10 条、原文合计最多 2,000 字符，条数可调为 1–20；单条超过字符预算时完整单独发送，服务拒绝会报错。翻译默认并发 3、每分钟最多 60 次请求，与转录限流独立，跨文件共享翻译请求额度。

模型结合批内上下文翻译，时间轴留在本地。程序通过固定编号回填乱序结果，校验缺失、重复、额外编号、空译文及未正常结束的响应；校验失败会递归对半拆批，单条仍失败则停止该文件。超时、连接错误、429 和服务端错误最多重试 3 次，尊重 `Retry-After`；鉴权、参数及模型错误直接报告。编号校验保障条目结构，无法证明译文语义完全对齐。

优先使用 JSON 的语言标记（支持常见两字母、三字母及地区代码），缺失时使用界面明确选择，再使用 `auto`。不通过汉字外观识别中文，不检测逐句混合语言。明确标记为中文的内容用 OpenCC `t2s` 本地转换，只输出简中且无需密钥；外语原文保持不变，模型译文也转换为简中。关闭自动翻译时沿用原有字幕排版和输出行为。

JSON 导入、单文件媒体和分段媒体共用后台字幕处理，界面显示完成条目数，支持取消；批量文件中一个失败会继续后续文件，取消会停止整个队列。最终仅保留源文件同名 `.srt`，不导出转录或分段 JSON；完整成功后原子替换，失败或取消保留已有 SRT。导入的 JSON 和已有同名 JSON 文件保持不变。

未完成的媒体字幕任务使用源文件旁的 `文件名.mp4.transcription-cache.json` 临时保留原始转录（保留媒体扩展名）；未完成的翻译保存在 `文件名.translation-cache.json`，包括已校验的译文及拆批进度，不保存密钥。只有媒体的规范化绝对路径、大小、纳秒修改时间，以及转录模型、源语言、声音事件和分段长度全部匹配时，才自动复用转录。文件身份不计算完整内容哈希；如果内容被修改但大小和修改时间都未变，无法识别这类变化。字幕排版和翻译设置变化不会强制重新转录。完整批次原文、源语言、翻译模型、官方地址、提示词版本或组批配置变化时相关翻译缓存失效。成功后清理本次任务缓存。旧格式或缺少任务身份的转录缓存不会自动复用或删除；旧普通转录 JSON 可通过 JSON 入口明确导入。取消会停止派发并忽略迟到结果，在途请求的连接/读取超时为 10/60 秒。

API Key 按本机配置明文保存到 `settings.json`，界面遮罩显示且日志不记录密钥。该文件已排除版本控制及发布打包；仓库只提供不含密钥的 `settings.example.json`。旧配置会自动补入新字段默认值。仅远程翻译需要填写密钥。

### 验证和打包

自动测试不连接真实服务；完整测试包含需要 `build` 依赖组的许可证解析测试：

```bash
uv run --locked --group build python -m unittest discover -s tests -t . -p "test_*.py" -v
```

正式 Windows 构建使用 uv 0.13.0、`.python-version` 固定的 CPython 3.15.0 x64
和 `uv.lock`。在 Windows 下运行：

```powershell
./scripts/build_windows.ps1
```

脚本使用 `uv sync --locked --group build`，校验解释器、两份 requirements 导出及依赖，
从同一环境运行离线测试、构建 EXE、附带许可证、生成 ZIP，并解压验证后生成 SHA-256。
可用 `-Uv` 指定 uv 可执行文件，用 `-ArtifactId` 指定包名中的版本标签或提交 SHA。
构建收集 OpenCC 数据、Qt Windows 插件和 HTTPS 证书；打包钩子过滤应用未使用的虚拟键盘及 PDF 插件。

修改依赖后更新锁文件和 pip 导出文件：

```bash
uv lock --upgrade
uv run --locked python scripts/export_requirements.py
uv run --locked python scripts/export_requirements.py --check
```

Windows 下也可用离线 JSON 单独验证真实 Shell 快捷方式的添加、更新、移除、源码版及打包版的单文件／多文件启动、不同工作目录的配置加载，以及最终 EXE 在无密钥、无 Python/FFmpeg 环境下的默认繁转简：

```powershell
uv run --locked --group build python tests/send_to_windows_smoke.py --executable build/<本次构建目录>/dist/Scribe2SRT.exe --send-to-directory build/smoke-sendto
```

传入 `--send-to-directory` 时，快捷方式操作全部使用指定隔离目录。省略该选项会临时更新当前用户的本程序快捷方式，并在结束时恢复原内容；同名但不属于本程序的快捷方式会拒绝覆盖。默认配置检查要求被测 EXE 旁没有 `settings.json`。所有应用烟雾测试子进程最多等待 60 秒。

推送 `main`、面向 `main` 的 PR 和手动触发都会构建并上传验证包；仅本 Fork 的 `v*` 标签推送在验证成功后创建正式 Release。详细构建、上线和失败重试步骤见 [Windows 发布操作](docs/windows-release.md)。

尚未使用真实凭据验证默认 10 条组批在 Qwen-MT 上的编号保留率、拆批频率及语义串句情况。实际使用时建议先用少量英、日、韩字幕比较每批 1 条与 10 条的译文。
